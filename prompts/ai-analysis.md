# AI Article Analysis Pipeline Implementation Prompt

## Goal
Implement the production-grade AI article analysis pipeline for Veritas News. The pipeline will automatically identify unanalyzed articles in Supabase, execute structured analysis using Vercel AI SDK (`ai`) with the Gemini provider (`@ai-sdk/google`), derive bias scores and framing percentages, validate output using Zod, persist results to `article_analyses`, mark articles as analyzed, and record execution logs.

## Decisions & Assumptions
1. **Packages**: Install `ai` and `@ai-sdk/google` to implement Vercel AI SDK structured generation with Google Gemini.
2. **Model Selection**: Use `gemini-2.5-flash` via `@ai-sdk/google` (with fallback configuration) for fast, accurate structured output and bias/framing analysis.
3. **Pending Check**: Strictly use `getPendingArticles()` which performs a LEFT JOIN of `articles` and `article_analyses` and filters in JavaScript where no analysis exists.
4. **Validation & Derivation**:
   - `bias_score` is derived as `(right_percentage - left_percentage) / 100`.
   - Framing percentages (`left_percentage`, `center_percentage`, `right_percentage`) are validated and normalized to sum to exactly 100.
   - Output validated using Zod. On schema failure, retry generation once before marking as failed.
5. **API Endpoint & Security**:
   - Exposed at `POST /api/analyze`.
   - Requires `x-veritas-admin-secret` matching `process.env.VERITAS_ADMIN_SECRET`.
   - Accepts optional JSON body: `{ "limit": number, "articleIds": string[] }`.
6. **Logging & Tracing**:
   - Progress and errors are logged to console and Supabase `logs` table.
   - Return clean summary object containing: `status`, `total_pending`, `analyzed_count`, `failed_count`, `duration_ms`, `errors`.

## Implementation Requirements

### 1. Library & Provider Setup (`lib/ai/client.ts`)
- Initialize `@ai-sdk/google` provider using `process.env.GOOGLE_GENERATIVE_AI_API_KEY || process.env.GEMINI_API_KEY`.
- Export default model instance: `google('gemini-2.5-flash')`.

### 2. Structured AI Analysis Engine (`lib/ai/analysis.ts`)
- Define Zod schema for structured output:
  - `summary`: string (1-3 paragraph neutral summary)
  - `sentiment_score`: number (-1.0 to 1.0)
  - `sentiment_label`: 'positive' | 'neutral' | 'negative'
  - `left_percentage`: integer (0-100)
  - `center_percentage`: integer (0-100)
  - `right_percentage`: integer (0-100)
  - `political_framing_label`: 'left' | 'center' | 'right' | 'mixed' | 'unclear'
  - `confidence`: number (0.0 to 1.0)
  - `framing_notes`: string (analysis of framing tone, headlines, and perspective)
  - `loaded_terms`: array of objects or strings detailing emotionally loaded phrases or bias indicators
  - `disclaimer`: string ("AI-estimated analysis. Framing and sentiment are generated by AI models and do not represent absolute factual truth.")
- System Prompt Guidelines:
  - Analyze news article based strictly on content text provided.
  - Do NOT infer political bias from publisher name; evaluate article content only.
  - Ensure left + center + right percentages total 100%.
- Execution logic:
  - Call `generateObject` with Zod schema.
  - Apply fallback normalization if sum of percentages is not 100%.
  - Compute `bias_score = (right_percentage - left_percentage) / 100`.
  - Include single-retry mechanism if initial generation or schema validation fails.

### 3. API Handler & Batching Orchestration (`app/api/analyze/route.ts`)
- HTTP Method: `POST`
- Authenticate request using header `x-veritas-admin-secret` against `VERITAS_ADMIN_SECRET`. Reject with 401 if missing/invalid.
- Fetch pending articles:
  - If `articleIds` provided, fetch specified articles.
  - Otherwise call `getPendingArticles(limit)`.
- Loop and batch processing:
  - Process pending articles sequentially or in micro-batches (e.g. concurrency of 2-3).
  - For each article:
    1. Call AI analysis.
    2. Save analysis to Supabase via `insertAnalysis()`.
    3. Update `articles.analyzed_at` via `markArticleAnalyzed()`.
    4. Log progress.
- Record run log entry in `logs` table via `createLog()`.
- Return detailed summary JSON response:
  ```json
  {
    "status": "success",
    "total_pending": 5,
    "analyzed_count": 5,
    "failed_count": 0,
    "duration_ms": 3420,
    "results": [...]
  }
  ```

## Security Requirements
- Require `x-veritas-admin-secret` request header on `POST /api/analyze`.
- Do not expose `GEMINI_API_KEY` or `SUPABASE_SERVICE_ROLE_KEY` to client.
- Return 401 Unauthorized for missing/invalid admin secret.

---

## Acceptance Criteria
1. Running `POST /api/analyze` processes all unanalyzed articles in Supabase.
2. `article_analyses` receives valid rows with `summary`, `sentiment_score`, `sentiment_label`, `bias_score`, `bias_label`, `left_percentage`, `center_percentage`, `right_percentage`, `confidence`, `framing_notes`, `loaded_terms`, `disclaimer`, `model`.
3. `articles.analyzed_at` is updated immediately after saving analysis.
4. Percentages (`left` + `center` + `right`) sum to exactly 100.
5. Derived `bias_score` equals `(right_percentage - left_percentage) / 100`.
6. API route rejects unauthenticated calls with 401.
7. Logs are recorded in Supabase `logs` table.
